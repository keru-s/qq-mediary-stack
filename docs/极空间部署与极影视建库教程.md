# 极空间部署 + 极影视建库教程

> 前提：镜像已就绪（二选一）：
> 1. 在电脑上运行 `./scripts/build-images.sh --platform linux/amd64 --save dist/mediastack-images.tar` 构建并导出，把 tar 传到极空间后用 Docker 面板「镜像 → 导入」；
> 2. 或已自行构建好 `mediary-scout-web`、`mediary-qqbot`、`mediary-strm-sync` 三个镜像（postgres/openlist/pansou 为公共镜像，面板可直接拉取，拉不动就配镜像源）。
> 部署时需要的文件：`docker-compose.yaml` 和 `.env`。
> 本教程全部使用极空间 Docker 面板的图形化操作，**不需要 SSH**（SSH 方式见文末附录）。

## 〇、端口与数据目录（先理解，再部署）

**端口**（已写在 compose 里，无需手动配）：

| 服务 | 端口映射 | 说明 |
|---|---|---|
| web（Mediary Scout） | `3300 → 3000` | 主服务，设置页和 agent API |
| openlist | `5244 → 5244` | 网盘挂载 |
| postgres / pansou / qqbot / strm-sync | 不对外 | 仅容器间内部通信 |

**数据目录**：compose 里所有数据都用 `./` 相对路径。极空间 Compose 面板在「新增项目」时会要求你**图形化选择一个「存储位置」文件夹**，所有 `./` 路径自动落在它下面，启动后你会在文件管理器里直接看到：

```
你选的存储位置/
├── pgdata/          # 数据库：夸克凭证、追更状态、任务记录
├── openlist-data/   # OpenList 配置和账号
└── strm/            # STRM 文件输出（极影视扫这里）
```

不需要查询或填写任何绝对路径——选文件夹就是在做路径映射。

## 一、在极空间上启动整套服务（约 10 分钟）

1. **建项目文件夹**：文件管理器里选好盘位，新建一个文件夹，比如 `Docker/mediastack`。

2. **导入镜像**：Docker 面板 → 镜像 → 导入，选择传上去的 `mediastack-images.tar`。
   完成后镜像列表应能看到 `mediary-scout-web`、`mediary-qqbot`、`mediary-strm-sync`、`postgres:16-alpine`、`openlistteam/openlist`、`ghcr.nju.edu.cn/fish2018/pansou-web` 六个镜像。
   （如果面板版本没有导入功能，见文末附录用 SSH 导入。）

3. **创建 Compose 项目**：Docker 面板 → Compose → 新增项目：
   - 项目名称：`mediastack`（随意）
   - **存储位置：选择第 1 步建的 `mediastack` 文件夹**
   - 粘贴 `docker-compose.yaml` 的内容
   - 环境变量（.env 可视化编辑）：把 `.env` 文件里的内容逐项填入（面板支持可视化配置环境变量）
   - 创建并启动

   备注：如果面板校验时报与 `build` 相关的错误，把每个服务里的 `build:` 那两行删掉再提交（镜像已导入，构建段用不上）。

4. **验证**：浏览器打开 `http://极空间IP:3300` 能看到 Mediary Scout 页面即成功。

5. **连接夸克**：Mediary Scout 设置 → 网盘 → 夸克 → 手机夸克 App 扫码。
   （网盘凭证存在数据库里，不随镜像迁移，这步必须重新做一次。DeepSeek 配置已在环境变量里，不用重填。）

6. **测一次**：QQ 里给 moviePilot 发个片名，确认 Mac 上跑通的流程在极空间上同样工作。

⚠️ **迁移完成后，确认 Mac 上的栈是停的**（我之前已停掉）。同一个 QQ 机器人凭证只能一处在线，两边同时跑会互踢。

## 二、OpenList 挂载夸克 + 配置 STRM（约 10 分钟）

极空间上的 OpenList 是全新实例（和 Mac 上验证用的那个数据不互通）：

1. **设一个固定的 admin 密码**（strm-sync 服务要用它登录 OpenList）：
   - Docker 面板 → 容器 → openlist → 日志，找到首次启动打印的初始密码
   - 浏览器打开 `http://极空间IP:5244` 登录 → 右下角头像 → 个人资料 → 修改密码，改成你自己的密码
   - 回到 Compose 项目的环境变量（.env 可视化编辑），把 `OPENLIST_PASSWORD` 改成同一个密码，**重新启动项目**让 strm-sync 生效

2. **挂夸克**：OpenList 网页 → 管理 → 存储 → 添加：
   - 驱动：**夸克 Quark**（不是夸克 TV）
   - Cookie：电脑登录 `pan.quark.cn` → F12 → 网络 → 刷新 → 点第一个 list 请求 → 复制整段 Cookie
   - **Web 代理/网页代理：开启**；WebDAV 策略：**本地代理**；转码：关闭
   - 挂载路径：`/quark`

3. **加 Strm 驱动**（管理 → 存储 → 添加）：
   - 驱动：**Strm**
   - 挂载路径：`/strm`（和环境变量里 `STRM_PATH` 一致）
   - 路径（paths）：`/quark/Mediary Scout`
   - 站点 URL：`http://极空间IP:5244`（**必须填极空间的局域网 IP**，手机/电视播放时要能访问到这个地址）
   - **带签名（withSign）：开启**（不带签名的链接会 401 无法播放；签名是永久的不会过期）
   - **保存 Strm 文件至本地：开启**，本地路径：`/strm`，保存模式：**更新模式**

4. 确认 strm-sync 在工作：Docker 面板 → 容器 → strm-sync → 日志，应看到「扫描完成：N 个目录、M 个文件」。STRM 文件会出现在你选的存储位置文件夹下 `strm/quark/Mediary Scout/...`。

## 三、极影视建库（约 3 分钟）

STRM 方案下**不需要 WebDAV 挂载**——极影视直接扫本地 STRM 文件，刮削过程零夸克 API 调用，规避网盘风控：

1. **极影视 → 添加分类**，建三个分类，分别指向你选的存储位置文件夹下 `strm/quark/Mediary Scout/` 里的：
   - 「电影」→ `Movies`
   - 「剧集」→ `TV`
   - 「动漫」→ `Anime`
2. 刮削设置选中文元数据，等首轮刮削完成。
3. 播放时极影视读 STRM 里的地址 → 经 OpenList 本地代理播夸克在线流，就是 Mac 上验证过的那条流畅链路。

**新内容如何进来**：QQ 点播完成时机器人会自动触发一次即时扫描，新片几分钟内就能在极影视出现；此外 strm-sync 每 6 小时（环境变量 `SCAN_INTERVAL_S`，不建议低于 600 秒）兜底扫描一次，追更补集的新集会自动进库。极影视那边设置定时自动扫描媒体库即可。

## 四、日常使用

- QQ 私聊 moviePilot 发片名 → 自动搜索转存进夸克 → strm-sync 定时生成 STRM → 极影视自动扫描 → 直接在线播放，全程不需要手动操作
- 追更的剧：Mediary Scout 会自动追踪缺集并补转存（定时巡检），新集同样经 strm-sync 自动进极影视
- 多候选歧义时机器人会发列表，回序号选择
- 机器人命令：`/状态` 查进行中任务；`/刷新` 立即触发媒体库更新（等不及兜底扫描时用）；`/帮助` 看说明
- 手动刷新 STRM 的另一途径：OpenList 网页里浏览一遍 `/strm` 存储的目录，或 管理 → 索引 → 手动扫描

## 五、故障排查

| 现象 | 排查 |
|---|---|
| 机器人不回消息 | 面板里看 qqbot 容器日志；Mac 上的栈是否已停（凭证互踢） |
| 播放卡 | 确认 OpenList 里夸克驱动开了本地代理、没开 302；别用极空间官方网盘挂载 |
| STRM 点了 401 不能播 | Strm 驱动没开「带签名（withSign）」；或改了站点 URL 后需要重新生成（更新模式下再扫一次） |
| 新转存的内容一直没进极影视 | 面板里看 strm-sync 容器日志；环境变量 `STRM_PATH` 是否和 Strm 驱动挂载路径一致 |
| 搜不到资源 | 面板里看 pansou 容器日志；ghcr 镜像源是否可用 |
| agent API 404/401 | 环境变量 `MEDIA_TRACK_AGENT_TOKEN` 是否填了且两边一致 |
| 转存失败 | Mediary Scout 设置页重新扫码（夸克 Cookie 会过期） |

## 附录：SSH 方式（备选，会用命令行的话更直接）

```bash
# 在 dist 目录下（镜像 tar 所在处）
docker load -i mediastack-images.tar
docker compose up -d          # 六个服务全部启动（qqbot 已改为默认启动）
docker compose ps             # 确认全部 Up
curl http://localhost:3300/api/health   # 应返回 {"status":"ok"}
```

SSH 方式下 `./` 相对路径以 compose 文件所在目录为根，即 dist 目录本身就是数据根目录。
